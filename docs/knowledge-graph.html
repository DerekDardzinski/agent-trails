1  Five kinds of record, and what each holds

Every record shares seven fields. The rest are per kind. latched means freeze makes it immutable; append-only means entries are added and never rewritten.

shared by every record

One representation of a title and one of a subject list. A composite record nests this rather than flattening it — goal.record.id is the id.

  • idper-kind prefix + 16 hex
  • kindgoal | hypothesis | experiment | claim | log
  • titleone line; a log entry has none
  • subjects[]free tags — this is what makes a record findable
  • authorOS user; recorded, nothing depends on it
  • created_atwrite-ordered sequence
  • bodyfree prose

goal

One per campaign. The framing a human confirmed and the plan that decides success.

  • framinglatched
  • analysis_planlatched
  • datalatched dataset + per-split digests
  • result[]append-only each with citation
  • statusactive | achieved | unresolved
  • frozen_atwhat the latch keys on

hypothesis

A claimed mechanism behind an observable's current value — not an intervention.

  • mechanismwhere it should operate, and where it should not
  • statusproposed | lead | supported | excluded | retired

Never edited into a different hypothesis. A revision is a new record linked refines, standing beside the original.

experiment

The schedulable unit. Four kinds: apparatus, probe, confirmatory, replication.

  • experiment_kindwrite-once
  • designlatched
  • analysis_planlatched absent for apparatus
  • procedurelatched split, arms, seeds, n, filter
  • frozen_observableslatched definition version per observable
  • frozen_harness_hashlatched
  • frozen_apparatus_idlatched ← the baseline pin
  • provenance[]append-only one entry per attempt
  • score_report[]append-only location + digest
  • result[]append-only verdict + cited values
  • battery_results[]append-only apparatus only
  • statusdraft | approved | running | closed | void
  • frozen_at

claim

This is where accumulated judgment lives. Findable by subject and by meaning, gated on admission, and its evidence is dereferenced and hashed on write.

  • claim_typefinding | literature | gap | method-note
  • descriptionwhat is claimed
  • outcomewhat was observed
  • methodshow
  • learningswhat it is taken to mean
  • scopethe conditions under which it holds

outcome and learnings never merge

Observation versus interpretation. A verified evidence pointer lends its authority to outcome and none to learnings. Merging them would let the unverifiable half borrow credibility from a digest.

the verdict, which lives inside result[]

One per arm. What the agent read off the harness — never something the store derives. The five are a CLOSED SET the store now refuses outside of. It does not decide what the verdict should be; it refuses a word in no vocabulary, because the hypothesis status rule is driven entirely off these words and the one place the code reads a verdict compares it against void alone — so before this landed, a misspelling read as a real conclusion and let the experiment verify as evidence for a finding.

  • rejectedthe null fell in the predicted direction and no guardrail regressed — the intervention worked
  • excludedthe interval lies entirely inside the minimum effect — an effect that would matter is ruled out
  • inconclusivethe interval spans the minimum effect — the experiment could not tell
  • guardrail_failedthe primary moved by degrading something that matters
  • voidno interpretable measurement; never counted as a negative result

The gap between the middle two is what makes a negative result usable: failing to reject is not evidence against a mechanism unless the test could have detected the effect. An apparatus experiment has no verdict at all — its outcome is the battery_results list.

log

The audit trail and every human decision. Addressed by its target, never retrievable by subject — a campaign writes hundreds, and a subject query returning machine audit rows beside findings would be useless.

  • targetthe record this attaches to
  • log_kindnote | amendment | mutation | check
  • tagthree values gate a command: methodology-review, review-skipped, validity
  • bodythe text

2  The edges

Colour is the category, and the category is the whole argument: an edge either does bookkeeping a machine walks, or asserts meaning a later agent must understand, or changes what a query returns.

structural — walked by ready or shown as a marker interpretive — carries a reason retrieval-affecting — changes the result set not an edge — evidence or log target

Why supports goes

Experiment-supports-hypothesis is already recorded: a hypothesis's supported status is derived from the verdicts of the experiments linked belongs_to it. A supports edge would be a second spelling of a fact the store already holds. And claim-supports-claim buys nothing actionable — both claims are independently findable by subject, so they surface together anyway, and missing a supporter costs an agent nothing. Missing a contradictor makes it overconfident, which is why that one stays.

3  The one edge that changes what comes back

presupposes is the only edge that adds records to a result. Everything else either steers a machine or gets shown as a marker on something already returned.

The admission test, since nothing can enforce it

Write this edge when a competent reader would draw a wrong conclusion from the first record alone, and the second is what prevents it. Not merely related, not merely useful — wrong without it. Over-applied, it makes every query more expensive and less readable, because the presupposed record is returned past the caller's limit, transitively.

4  Where a reasoning lives

Two places, and the choice is not a matter of taste. An edge's reasoning is cheap, always written in the same call, and reachable only by someone already holding one endpoint. A claim is findable by subject, carries a scope, is gated on admission, and its evidence is verified.

Would a future agent want to find this holding neither endpoint?

yes →It is a claim. Subject-tagged, retrievable by meaning, scope records the conditions it holds under, evidence pointers at the experiments are dereferenced and verified on write. The edge's reasoning then just names the claim.
no →It is the edge's reasoning. One line, legible only beside that pair, so the graph is not mute. “H2 supports F1 because F1's effect was measured on the same subpopulation H2 predicts” — nobody will ever search for that.

This is the same test the design already draws between a log entry and a claim: the difference is what finds it. And it explains the audit finding cleanly — three of the interpretive edges are read by nothing today because they carry nothing.

Why judgment belongs in claims, not edges

Findability. At the moment that matters — an agent about to propose a hypothesis — it holds a subject and nothing else. Retrieval covers goal, hypothesis, experiment and claim. An edge is reachable only if you already hold an endpoint, so reasoned edges are knowledge you can only find if you already knew where to look.

The quality gate. A finding is admitted only against seven criteria — confirmatory, plan frozen first, test split, replicated, no guardrail regression, not void, scope recorded. An edge is gated by nothing. Make edges the carrier of takeaways and you have built a second, ungated channel for exactly the content that gate exists for.

Transfer. A claim states a mechanism and the conditions it holds under. An edge states a relation between two specific artifacts. Retrieval by correspondence of mechanism transfers; retrieval by surface similarity does not.

The link row, before and after

before pmem-cp0

Four columns, three of them ids and an enum. No id, no author, no time, no reason — the least accountable row in a store whose whole premise is provenance.

  • from_id
  • to_id
  • link_type
  • qualifier'' for everything but depends_on

as built today landed

Free while the database was being recreated anyway. Retrofitting it later is now possible rather than impossible: an existing database is upgraded in place on open by a runner that observes the schema, so a column can be added without deleting a populated store.

  • from_id
  • to_id
  • link_type
  • qualifier+ conflict kind on contradicts
  • reasoningfree text — interpretation, unverified
  • author

Classifying a contradiction

Prose an agent must interpret, plus a value it can branch on. Three of these mean reconcile the records; one means the science is unsettled.

scopethey hold under different conditionsnarrow a scope statement — apparent conflict
measuredifferent observable or definition versionnot comparable; re-freeze or re-measure
datadifferent dataset or splitnot comparable
directsame conditions, same measure, opposite resultdesign a discriminating experiment

6  What retrieval returns, and what it hides

kindfindable by subject and meaning?why
goal · hypothesis · experiment · claimyes knowledge is addressed by what it is about, not by which campaign produced it
lognever addressed by its target; a campaign writes hundreds and they would drown findings
probe experimentsexcluded by default cannot be cited, so returning one invites a citation in every sense that matters
void recordsexcluded by default not a result — an agent that reads one and reasons from it has cited it
superseded recordsreturned, marked reads carry superseded_by so the reader knows a newer one exists
refined recordsreturned, marked reads carry refined_by — a refinement stands BESIDE the original rather than replacing it
confirmatory experimentsreturned with a replication count a finding needs replication, so one returned without the count is materially incomplete

A flag includes the excluded two for deliberate review of provisional work.

7  What is not a record

evidence

Typed pointers hanging off a claim. Dereferenced and hashed on write — a model may propose one, only a mechanical check may mark it verified.

  • evidence_kindcode · document · artifact · search · experiment
  • payloadper-kind JSON

verification

One row per dereference. No row means the check never ran — a different statement from a check that found nothing.

  • outcomeholds · mismatch · absent · unresolvable
  • policy_versiona pass means nothing if the rule can drift

subject · tag_alias · embedding

The retrieval machinery. Aliases fold two tags meaning the same thing, which is the failure that otherwise splits a corpus in half.

Nothing here is enforced except the freeze latch, append-only records and links, the verified write path, the citation fields, two record-existence preconditions, a gap claim needing search evidence, and a refused dependency cycle. Everything else is a rule an agent follows, and the store's job is to make a violation visible afterward.
